# Инструкции для Codex

## Контекст проекта

PhpTools - библиотека инструментов для PHP 8.1+.

* Основной код находится в `src/` и подключается через PSR-4 namespace `DraculAid\PhpTools\`.
* Юнит-тесты находятся в `tests/` и подключаются через PSR-4 namespace `DraculAid\PhpTools\tests\`.
* Документация на русском языке находится в `Documentation-ru/`.

Основные области библиотеки:

- `src/Classes` - работа с классами, объектами и паттернами.
- `src/Code` - инструменты для работы с кодом.
- `src/ExceptionTools` - работа с исключениями и PHP-ошибками.
- `src/DateTime` - работа с датой и временем.
- `src/Arrays` - инструменты для массивов и массивоподобных объектов.
- `src/Strings` - инструменты для строк и символов.
- `src/TestTools` - вспомогательные инструменты для юнит-тестов.

## Обязательные инструкции

Перед изменением кода учитывай:

- [CODE_STYLE.md](CODE_STYLE.md) - код-стайл и правила оформления.
- [tests/AGENTS.md](tests/AGENTS.md) - правила написания и запуска тестов.
- [tests/README.md](tests/README.md) - существующие команды тестов и Psalm-проверок.

## Правила работы с проектом

- Следуй существующим паттернам соседнего кода.
- Не меняй публичное API без явной необходимости.
- Не совмещай небольшие исправления с крупными рефакторингами.
- Не удаляй существующие тесты без причины.
- Для новой логики добавляй или обновляй тесты.
- Если проверку нельзя запустить, явно укажи причину.

## Изменения кода

- При исправлении бага старайся менять минимально необходимый участок.
- При добавлении метода проверь, нужен ли тест и ссылка на тестовый класс в PHPDoc, если такой паттерн уже есть рядом.
- Не меняй поведение существующих методов без теста или явного объяснения.
